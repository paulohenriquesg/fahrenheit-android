The podcast screen: every episode, and whether the server has it

The goal: open a podcast and see everything in its feed, with what is on the server told apart from what is not. Today the screen only knows what the server has downloaded, so for 102 of 134 podcasts it shows nothing. Built on PR #77 (check for new episodes) and the #75 branch (why it is empty).

Each frame is a real 1920×1080 screen at half scale. px = dp × 2. Admin-only where marked: the feed endpoints answer 403 to anyone else.

A. An admin opens a podcast admin

The server reads the feed (POST /podcasts/feed) and matches each episode to what it holds, by guid or enclosure URL, the same rule it uses itself. A tick means it is on the server and plays now; a dashed circle means it is only in the feed. The tabs split the two, with counts, and open on All. Heard episodes say so; a half-heard one shows how far. Centre on a missing episode downloads that one episode: the action is spelled out on the focused row, so a press never fetches something unexpected.

A2. While it downloads admin

The server reports its queue (GET /podcasts/:id/downloads), so a download started from the TV is watched, not guessed at. The row turns into a tick when the file lands and becomes playable in place. This is step 3 of #76; without it the row would just say "Queued".

Decided, 2 October

Settled in conversation
  1. The feed is read on open for an admin, every time. Its episodes are not stored; the server fetches the RSS.
  2. Centre on a missing episode downloads it straight away, with no confirmation. The focused row spells out the action.
  3. All is the first tab.
  4. "Check for new episodes" stays: the one-press way to get the newest three.
  5. The cover stays on every row, so it is already in place when per-episode covers arrive.
  6. Heard episodes are marked, and half-heard ones carry a progress bar, from one /api/me call. This also settles the progress-bar question in screens.html.
  7. Empty podcasts on the grid are dimmed and keep their count line.
  8. The player gets "Go to podcast" when it is playing an episode: see frame 4b in screens.html.
  • Mocked: the two "Example" episode titles (the feed is not stored, so its real titles are not to hand), the covers, the percentages, the progress, and the episode counts for NerdCast and Night Vale. The facts, the Tabstack and Anvil rows, and the Auf den Punkt dates are real.
