Login screen — mock before implementing

The constraint that shapes all of this: the Fire TV keyboard owns the bottom 45% of the screen. Anything below the dashed line is invisible while you are typing, which is why the current screen hides its own error messages. Jellyfin's 0.14 redesign solved it the same way — move the form up and keep errors beside the field. Their Quick Connect (a code authorised on your phone, no password on the TV) needs server support Audiobookshelf does not have.

1. First run — find the server instead of typing it

An address is 24 characters of punctuation on a D-pad; a password is 19 key presses. So scan the subnet for port 13378 and offer what answers. Typing an address becomes the fallback, not the default. Everything sits in the top half, clear of the keyboard.

What this costs, in order

  • Already done (not yet merged): outlined fields instead of near-white slabs, the phone components given the app's palette, and the form capped at 720dp.
  • Small: move the form into the top half, put errors beside the field, and show the server as a fact once it is known.
  • Medium: subnet scan for port 13378 — removes the worst typing on the device. Needs a timeout, parallel probes, and a manual fallback.
  • Not available: a phone-authorised code like Jellyfin's Quick Connect. That is a server feature, and Audiobookshelf has no equivalent endpoint.
  • Open question for you: the remembered-user row in frame 3 — one user is all this device has ever seen. Worth keeping a list if more than one person signs in on the same TV?
